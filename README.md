# 塔

随便堆，堆多高都行。堆好了，一巴掌推倒。

线上站点：https://lllllf-hhhhhq.github.io/ta-tower/

一个 3D 堆塔小游戏。建设与毁灭两个爽点在同一个场景里闭环：先靠手感把塔垒起来，再按空格横扫推翻。

## 玩

打开 `index.html` 即可，单文件、无需联网、无需服务器。也可以直接开线上站点。

- 移动鼠标：瞄准落点
- 按住左键：砖缓缓下沉；松开左键：松手
- 滚轮：调悬停高度（决定这一块是轻放还是砸下去）
- Q / E：转砖的朝向
- 空格：一巴掌推倒；W / S：挪扫击高度
- 右键拖动：转视角；R：重来

地上的彩色方框是落点预判：绿色稳、黄色临界、红色必塌。砖贴到支撑面后再松手是零冲击的轻放；还悬在半空就松手，会带着下坠速度砸下去。悬停的砖带阻尼跟随鼠标，松手那一下如果鼠标在动，横向速度会传给砖，塔越高越经不起这一抖。

## 技术

Three.js r160 + Rapier 0.14（WASM）。刚体堆叠是物理引擎最难的部分，接触点求解会留下两件事：整塔以约 0.06 m/s 缓慢漂移，个别砖以 2 m/s 高频抖动而位置几乎不动。速度判据永远进不了入睡，所以入睡判据改为**位置与姿态是否真的变了**：0.3 秒内位移小于 3 cm 且转角小于 1.4° 就冻结该刚体。真要倒的砖位移会迅速放大，不会被误冻。加上这层之后，24 块、8.6 米高的塔整体倾斜只有 0.8°。

另外两个真 bug 记在这里，都是在实测里抓出来的：

- 唤醒后没有重置入静计时。高刷屏下物理步进不是每帧都走，被唤醒的砖在完成速度积分前就被重新冻住，速度直接归零，导致一巴掌扫过去的冲量全部落空。
- 支撑面高度计算引用了方块记录上不存在的字段，得到 NaN，于是每块砖实际都按台面顶面生成，靠求解器把自己从塔内部挤上去。这是早期各种抖动、不睡、早塌的根源。

`contact_natural_frequency` 调到 2 / 4 反而更不稳，`switchToSmallStepsPgsSolver()` 与默认求解器无差别。最终用默认求解器：dt 1/60、迭代 8、摩擦 1.0、阻尼 0.22 / 0.5。

## 仓库结构

```
index.html        打包产物（GitHub Pages 入口，由 CI 构建）
dev.html          开发版入口，走 ES Module 从 libs/ 加载
src/game.js       游戏逻辑源码
build.mjs         打包：把 three + rapier + 源码合成单文件
dev-server.mjs   开发用静态服务器
libs/             three.module.js、rapier.es.js（CI 从 npm 取，不入库）
```

本地跑 `node build.mjs` 会产出 `index.html`（GitHub Pages 入口）和 `塔.html`（同一份内容，中文名方便直接打开）。这两份产物加起来 3.4 MB，不入库；线上站点由仓库里的 GitHub Actions 用同一套流程构建后发布。

改完 `src/game.js` 之后跑 `node build.mjs` 重新打包。开发时用 `node dev-server.mjs` 起服务，浏览器打开 `http://127.0.0.1:8123/`。

控制台里有调试钩子 `window.__tower`：`aim(x,z)`、`place()`、`drop()`、`slap()`、`reset()`、`stats()`、`dump()`，可以脚本化垒塔与推倒，方便调手感参数。
